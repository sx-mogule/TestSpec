# 前向测试矩阵

对 Skill 进行有意义的改动后，可用此矩阵运行真实提示词。
重复运行时，使用 [forward-evals.json](forward-evals.json) 中的机器可读配套数据。

## 目标

确认 Skill 能处理有代表性的用户请求，不依赖维护者隐藏的上下文。

## 测试用例

### 1. 评审模式

- 提示词类型：评审现有特性文件
- 最低来源要求：一个薄弱的特性文件，加上一份更可靠的事实来源材料
- 通过标准：
  - 指出使用的判定依据
  - 按严重度排列重要问题
  - 指出覆盖缺口
  - 不臆造元数据

### 2. 改写模式

- 提示词类型：改进现有场景
- 最低来源要求：一组薄弱场景
- 通过标准：
  - 保留业务意图
  - 改进命名和可观察结果
  - 不属于业务行为的 UI 操作流程应予以删减

### 3. 生成模式

- 提示词类型：根据验收标准创建 BDD
- 最低来源要求：用户故事和验收标准
- 通过标准：
  - 生成连贯的特性结构
  - 包含来源支持的主路径和错误路径
  - 列出未解决的假设，不臆造缺失规则

### 4. 混合模式

- 提示词类型：根据需求评审并改进材料
- 最低来源要求：已有草稿和验收标准
- 通过标准：
  - 先简短列出问题
  - 明确说明判定依据充分程度和可信度
  - 接着给出修订后的材料
  - 明确标记无法判定的事项

### 5. 正式报告模式

- 提示词类型：生成评分卡或执行报告
- 最低来源要求：特性文件和权威来源材料
- 通过标准：
  - 使用正式报告结构
  - 区分评审发现与信息缺失
  - 给出可执行的辅导建议

## 失败信号

如果 Skill 出现以下问题，则本次运行视为失败：

- 根据薄弱来源材料声称有很高可信度
- 臆造标签、ID 或业务规则
- 偏离到特定框架的自动化设计
- 将重大问题埋在笼统表扬中
- 改写后的材料在没有解释的情况下改变来源支持的业务意图
