# 行为检查清单

校验 Skill 改动时使用此清单。

## 触发行为

- 用户请求 BDD 评审、改写、生成或正式报告时，Skill 会触发。
- 用户只问通用测试、框架自动化或无关工程任务时，Skill 不会触发。

## 接收行为

- Skill 会说明所使用的判定依据来源。
- 适用时，Skill 会报告判定依据充分程度：strong、partial 或 weak。
- 事实来源不完整时，Skill 会降低可信度。
- Skill 不会臆造来源不支持的业务规则或元数据。

## 评审行为

- 用户要求评审时，Skill 会先列出评审发现。
- Skill 会将已确认缺陷与假设或信息缺失区分开。
- Skill 会按严重度排列重要发现。
- Skill 会指出 UI 脚本式 Gherkin、混合分支和含糊结果。
- 材料质量良好时，Skill 可以写 `No material defects identified`（未发现实质性缺陷）。

## 改写行为

- Skill 会保留业务意图。
- Skill 会改进场景命名和可观察结果。
- Skill 会拆分过载场景。
- 除非用户明确要求，否则 Skill 不会增加实现细节。

## 生成行为

- Skill 从业务规则、验收标准或示例开始，而不是从自动化步骤开始。
- 来源支持时，Skill 会包含主业务路径。
- 只有来源支持时，Skill 才会增加替代或错误路径。
- Skill 会明确标记未解决的假设和缺失的规则分支。

## 混合模式和报告行为

- Skill 会在 `hybrid` 回复中明确说明判定依据充分程度和可信度。
- 仅当用户要求正式报告、评分卡或执行摘要时，Skill 才使用正式报告结构。

## 边界行为

- Skill 不会创建用户不可见的持久记忆。
- Skill 会明确说明由用户指示的项目内持久化行为。
- Skill 会将共享记忆视为外部集成边界。
- Skill 可在兼容 Agent Skills 的宿主之间移植。
