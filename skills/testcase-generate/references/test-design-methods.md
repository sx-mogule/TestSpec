# 九种测试用例设计方法

生成前按测试点选择方法，可组合使用；不要为了凑方法而增加无证据场景。

## 1. 等价类

把输入按相同业务行为划分为有效类和无效类。有效类尽量合并覆盖，无效类通常一次只覆盖一个原因。

例：三角形判断输入 `a、b、c`：

- 有效类：纯数字，且任意两边之和大于第三边；数据 `3、4、5`。
- 无效类：含非数字字符；数据 `1、啊、%`。
- 无效类：任意两边之和小于或等于第三边；数据 `1、2、3`。

其他输入校验也先分组，例如 QQ 号“5–10 位纯数字、非 0 开头、以 `@qq.com` 结尾”，手机号码“11 位纯数字、首位 1、第二位大于 2”。

## 2. 边界值

作为有序等价类的补充，选上点、内点、离点；只对存在顺序和范围的条件使用。

例：QQ 号长度闭区间 `[5,10]`：

- 上点：5、10
- 内点：7
- 离点：4、11

例：ATM 每次取款 `100 ≤ money ≤ 5000` 且必须为整百：

- 有效：100、2000、5000
- 无效：0、99、101、5100

## 3. 判定表

适用于多个条件共同决定结果的规则。步骤：列条件桩 → 条件项 → 动作桩 → 动作项 → 合并相同结果的组合。

例：手机能否打电话：

| 欠费 | 手机损坏 | 结果 |
|---|---|---|
| 是 | 是 | 不能 |
| 是 | 否 | 不能 |
| 否 | 是 | 不能 |
| 否 | 否 | 能 |

无意义条件用 `-` 合并，减少重复用例。

## 4. 流程分析

按业务场景拆成核心流和备选流：核心流验证正常完成，备选流验证退出、取消、返回、失败和异常分支；每个阶段都检查用户可见结果。

例：提交订单：进入页面 → 填写信息 → 确认支付为核心流；取消支付、返回修改、支付失败为备选流。

## 5. 状态迁移

先列状态和合法迁移，再用尽量少的流程覆盖每条迁移，同时补充非法迁移。

例：随身听状态“停止、播放、快进、快退、暂停、录音”：

- 合法流：停止 → 播放 → 暂停 → 播放 → 停止
- 合法流：停止 → 录音 → 暂停 → 录音 → 停止
- 非法迁移：录音状态直接快进，验证系统拒绝或保持原状态

## 6. 错误推断

根据经验预判容易出错的地方，作为需求测试点的补充；必须能写成可观察的失败结果。

例：共享单车流程补充服务器超时、网络中断、数据保存失败、二维码损坏、电量不足、重复开锁等场景，分别验证提示、回滚、重试和状态一致性。

## 7. 正交实验

当多个因子和水平组合过多时，选择具有代表性的均衡组合；重要功能可增加组合，普通功能通常控制在 15 条以内。

例：发红包有“红包类型、支付方式、密码方式”3 个因子、各 3 个水平，全组合为 `3×3×3=27`；使用 `L7` 思路缩减为 7 组左右，同时保证各水平和两两组合均衡出现。

例：筛选有性别 2、年龄 4、区域 5、肤色 4 个因子，全组合 `2×4×5×4=160`，先用混合正交挑选代表组合，再按风险补充关键组合。

## 8. 因果图

从需求找出条件和结果，标出条件-条件、条件-结果、结果-结果关系，转成判定表并合并化简，最后生成用例。

例：自动售货机：

- 条件：投 5 角、投 1 元、按橙汁、按啤酒、有零钱。
- 结果：出橙汁、出啤酒、红灯、退 1 元、找 5 角。
- 关系：投 1 元且按下按钮且有零钱 → 找 5 角；选择橙汁和啤酒互斥；出橙汁与出啤酒互斥。

## 9. 配对组合（Pairwise）

当多个因子组合很多、但主要风险来自任意两个因子的交互时，优先保证每一对水平至少出现一次，再按风险补充三因子及以上组合。它比全组合少，比单因子覆盖更能发现组合缺陷。

例：浏览器（Chrome、Safari）、设备（手机、平板）、网络（Wi-Fi、4G）共有 8 组，全组合可缩减为覆盖所有两两组合的 4 组：

| 浏览器 | 设备 | 网络 |
|---|---|---|
| Chrome | 手机 | Wi-Fi |
| Chrome | 平板 | 4G |
| Safari | 手机 | 4G |
| Safari | 平板 | Wi-Fi |

## 方法选择提示

- 输入规则有分组：等价类；有明确范围：边界值
- 多条件决定结果：判定表或因果图
- 多步骤、多分支：流程分析；多状态切换：状态迁移
- 经验性故障补充：错误推断
- 因子很多且需均衡抽样：正交实验；重点保证两两交互：配对组合

## 用法与输出要求

1. 先根据测试点特征选择一种或多种方法，并在 `_context.design_methods` 记录方法名。
2. 只生成有需求依据的组合；无法确认的规则回到需求分析，不自行补全。
3. 用例内容短句化：一个步骤一行、一个预期一行，按 `1、2、3` 编号；避免背景说明、长段落和重复描述。
4. 预期结果必须紧跟对应操作步骤，能直接判断通过或失败。
