# 用例生成质量闭环

## 确定性门槛

按以下方式解释 `validate_testcases.py` 结果：

- PASS：继续；若有 `review_candidates`，按组交由 Review H1 复核全部成员和实际相似对
- WARN：逐项检查 warning，并修正高影响问题
- FAIL：修复全部错误后重跑
- `coverage.pass=false`：为列出的 TP ID 新增或修复用例

常见修正：

| Finding | 修正 |
|---|---|
| MISSING_FIELD | 补充必需的可执行内容 |
| INVALID_PRIORITY | 按风险使用 p0/p1/p2（小写） |
| DUPLICATE | 只合并真正重复项；否则区分意图 |
| SIMILAR_CASES（复核候选） | 对比条件、数据、边界位置和预期；有必要差异就保留，不凭相似度合并 |
| NAMING_FORMAT | 恢复“模块_功能_场景”标题 |

## 结构复核

- 完整集对全部 TP 的覆盖率至少 95%，并列出所有未覆盖 TP；Smoke 请求不缩小分母。
- Functional/boundary/exception 覆盖必须符合当前证据。
- `type=冒烟` 和 `regression_tier=Smoke` 的用例必须为 p0，类型为冒烟时同步 Smoke 层级；分类仍保留在完整集交付中，不派生独立文件。
- 全 p0 或全 p2 分布触发检查，不能按配额重写。
- 标题模块与 `feature` 一致。

## 消费者视角复核

在脑中逐条执行用例：

- 场景名称能直接看出主要意图，与步骤、预期一致；删掉套话和重复背景后，关键条件仍可区分。按共享命名契约改写名称，不能仅凭脚本 PASS 跳过语义复核。
- 四项描述按 `case-design-rules.md` 逐条复读：只保留执行和判定必需的条件、数据、动作与结果，删除套话、重复背景、绕行操作和无关检查。简单场景直接写，不人为增加准备、数据组合或预期数量；必要信息不得为缩短而省略。
- 前置条件直接写必需状态；测试数据只留本例操作和判定必需的字段和值，优先单行。删去整套配置、无关素材明细和重复背景；精确取值、单位、边界及必要组合保留，无必要数据时留空，不把删掉的冗余内容搬到其他字段。
- 步骤直接写动作和对象，不依赖另一用例的结果。
- 预期结果直接写可观察、可证伪的状态或变化，能对应相关步骤。
- 不按字数或步骤与预期的数量差判断质量；逐条核对主要目标是否有预期，缺少关键结果时补齐，不写无关内容凑数。
- 用例可重复，且每条只承载一个意图。
- 相似用例不能只是替换名词的模板副本。
- 相似候选须核对数值、单位、空值、角色、状态和边界位置。需求支持的最小合法值、最大合法值和越界值等必要边界即使结果相同也保留；同一等价类中仅换普通数值的用例评估合并。记录复核原因，不用改写标题避开相似度。

## 修正闭环

持续修正到确定性门禁通过；遇到缺失的产品规则时回到上游澄清，不用猜测填补：

1. 只修正明确指出的问题。
2. 重跑确定性校验。
3. 只有校验通过后才重新导出。
4. 在 `_context` 记录迭代次数和修正摘要。
5. 四项描述 finding 修复后重新 Review；由 Review 确认 resolved 并重算描述门禁，生成阶段不得自行清零问题或声明最终通过。

规则改动确需样例挑战时，只复用公共 eval 中 synthetic/non-proprietary 样例；真实历史用例与裁决仅在项目本地回放。原始材料、可判定 Oracle 或可靠裁决缺失时，列明证据缺口，不编造历史样本或声称完成回放。样例挑战不替代完整集 Review。

不得仅为满足指标就忽略 warning、扩大范围或虚构产品规则。

默认校验输出为按组摘要，逐对明细与缓存规则见共享 `execution-efficiency.md`。缓存命中不替代本次业务语义复核；`--no-cache` 可强制重跑，`--full` 可只读输出完整结果。返修只改已定位的问题，完成后仍做完整校验。

## 质量属性

最终用例集必须独立、可重复、可执行、可验证、清晰、完整且单一职责。
