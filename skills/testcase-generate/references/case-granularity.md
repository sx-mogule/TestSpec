# 用例粒度控制

## 复杂度自适应生成

> 用例数量由独立业务场景和覆盖目标决定，不设每个 TP 的最低或最高条数。复杂度用于判断需要分析的维度，不换算为用例配额。

在已确认需求和上游所选设计方法范围内，根据复杂度检查展开是否充分：

- **简单**（单一输入、明确规则、无状态变化）：覆盖适用的等价类和必要边界，不重复更换普通值凑数。
- **中等**（多输入组合、有状态转换、涉及权限）：覆盖影响结果的条件组合、状态迁移及权限分支。
- **复杂**（跨模块交互、复杂业务规则、多角色协作）：梳理主路径、关键异常及协作顺序，保留需求要求的组合与中间检查。

复杂度判断信号：

- 验证要点涉及的独立业务条件、状态及相互作用，不按要点数量直接换算用例数
- 上游已确认风险的业务影响与证据；按具体风险补查，不因模块被提及就机械增加用例
- 涉及的条件组合数（条件越多 → 越复杂）

**优先级分布由 Agent 根据风险判断，不设固定比例**：

- 核心正向路径、阻塞性功能 = p0
- 常规业务功能、重要边界 = p1
- 低频功能、边缘探索、体验类 = p2
- 在完整集中标记 Smoke 场景，标准：p0 且失败会阻塞大部分功能的最短业务闭环；该标记不改变完整集交付范围

## 何时拆分

- 多个独立功能验证维度（业务数据准确性、界面状态等）
- 不同验证点失败时影响不同
- 拆分后能更精确定位问题
- 需要完全不同的测试数据
- 同一功能的不同验证点有不同优先级

## 何时合并

- 验证点高度相关，属于同一原子操作的不同表现
- 操作步骤完全相同，只是观察角度不同
- 某些验证点必须在同一操作流程中完成
- 拆分只增加重复准备或执行，未增加独立覆盖
