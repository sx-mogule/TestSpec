# 评审报告模板

## 通用评审反馈

本节在 SOP 检查前形成并完整保留，展示同一模型按通用规则得到的原始反馈。后续复核可以补充处置，不能删除、改写或只引用 SOP 问题来代替本节。

**通用评审状态**: <已完成/未完成>
**执行方式**: 同一模型按通用评审规则单独评审
**评审依据与范围**: <实际读取的需求、用例/套件/BDD范围及来源限制>
**已检查内容**: <实际检查的覆盖、边界、错误路径、Oracle、可执行性等及证据摘要>
**通用发现数**: <count>
**通用评审结论**: <依据原始材料得出的结论；已完成且为0项时明确写“未发现实质性缺陷”>
**未完成原因**: <仅未完成时填写具体原因；已完成时删除此行>

有发现时逐项填写以下结构；使用 GR-001、GR-002 等本轮稳定编号，并删除占位说明。没有发现时删除示例发现，不为凑数编造问题。

**定位**: <需求/用例/场景编号及原文位置>

### 执行摘要

1. 总体评估等级
2. 主要优点
3. 严重问题
4. 建议优先级

### 需求分析与追溯

1. 需求清晰度评估
2. 需求到测试的追溯矩阵
3. 已识别的风险和依赖

### 测试套件结构评审

1. 层级评估
2. 组织结构建议
3. 重复与缺口分析

### 覆盖分析

1. 需求到测试的映射摘要
2. 覆盖指标
3. 测试设计方法使用情况
4. 缺口与过度测试分析

### 技术正确性验证

1. 判定依据是否恰当
2. 测试逻辑一致性
3. 数据质量评估

### 规范符合性评审

1. 模板遵循情况检查清单
2. 标题质量评估
3. 可选字段使用情况

### 辅导与提升计划

1. 优点
2. 提升空间
3. 针对性提升项
4. 具体辅导建议

### 评分矩阵

1. 需求覆盖
2. 技术正确性
3. 规范符合性
4. 测试设计成熟度
5. 文档质量
6. 整体质量

### 行动计划

1. 执行前立即采取的行动
2. 短期目标
3. 长期提升事项

### 元数据

1. 评审人
2. 评审日期
3. 评审耗时
4. 后续跟进日期（如需要）
