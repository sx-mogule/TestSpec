# 资料加载、检查结果复用与候选复核

适用于四阶段。只减少重复工作，不跳过阶段，不改变覆盖率、Oracle 或 Review 门禁。

## 按需读取规则

- 首次使用时读取入口及当前阶段必需的共享契约；同一会话已读且内容未变的规则不重复展开。
- 分析模式、输入适配、测试类型按当前任务选择；没有蓝湖或HTML输入时不加载对应适配说明。
- 测试点阶段保留十二种方法目录，按需求特征读取适用章节；生成阶段按上游 `design_methods` 读取对应方法，不重选全部方法。
- 八字段、上下文、来源与命名规则以共享契约为准。完整模板只在首次生成、格式不熟悉或返修该格式时读取。
- 一个参考文件里的其他分支不因文件存在就全部加载。遇到新的类型、规则或缺口时补读相关章节。

## 复用已读材料

可用 `../scripts/fingerprint_inputs.py` 对本阶段实际使用的原始材料、canonical、直接上游和规则文件计算SHA-256；需要比较时传 `--previous <上次摘要.json>`。工具只返回哈希及新增/变化、移除、未变路径，不复制原文。

`removed` 表示旧摘要里的路径不在本次输入清单中；先区分本阶段不再使用和实际文件删除，不为已排除的无关材料重复阅读。

- 只有原文已在当前会话读过且仍可用，内容哈希也一致时，才复用已读内容。哈希相同不代表此前已读，更不代表业务结论已通过评审。
- `changed` 或 `removed` 非空时，重读受影响材料，按原版本和 stale 规则更新下游。新上传、新链接版本、规则变化都要检查；版本号相同但内容变化也不能复用旧结论。
- 会话压缩或切换后，若原文已不在上下文，按当前任务重新读取必要部分；旧摘要不能替代需求证据。
- 每阶段仍执行版本检查。修正轮次只处理已发现的问题；完成后执行全量确定性检查。最多两轮的限制保持不变。

## 用例校验输出与缓存

`validate_testcases.py` 默认输出按组摘要，完整逐对明细保存在变更目录 `.testspec-cache/validation/` 的JSONL文件中；`duplicate_details` 给出路径、行数和SHA-256。`artifacts/` 中的正式JSON和XMind不增加其他文件。

- `summary.review_candidate_count` 是相似对总数；`review_candidate_group_count` 是摘要组数。`warning_count` 仍统计问题总数，摘要中的同类重复问题可按组展示。
- 输入、canonical、分析或相关规则内容变化，缓存失效；明细缺失、哈希不符、缓存损坏时重新检查。缓存只复用确定性检查，不复用模型评审结论。
- `--no-cache` 强制重跑并保存明细，不读写结果缓存；`--full` 输出完整逐对结果，不创建任何内部文件。需要其他明细位置时使用 `--report-dir`。
- 缓存命中仍须按当前输入做上下文版本检查；Review Gate由本次评审决定。检查PASS不能替代业务语义复核。
- 内部缓存可随变更归档后清理，删除后重新计算，不影响正式产物；不把缓存作为交付物。

## 逐组复核候选

候选组是相似关系的连通组，不代表组内任意两条都相似，更不代表应合并。

1. 读取组内全部用例，比较角色、状态、数值、单位、空值、边界位置和预期。
2. 共同内容按组比较一次，每个成员的实际差异都要核对。需要确认关系时读取JSONL中的对应相似对，不把全部重复文字塞入上下文。
3. 为所有成员记录保留或合并理由；上下边界等必要场景继续保留。无法确认差异价值时继续查需求，不按组自动删除。
4. 逐对明细不截断、不抽掉成员。组只改变展示方式，完整输入和原有14项评审仍要完成。
