# 来源与信任规则

## 权威顺序

1. 当前 PRD、验收标准和用户明确确认内容
2. 当前版本的接口或设计说明
3. 已评审的测试点与测试用例
4. 历史用例，仅用于命名、表达风格和回归提示

代码实现和历史行为不能覆盖当前需求事实。需求冲突或缺失时回到 `prd-analysis` 澄清。

## 产物来源

当前流程生成的用例使用：

```json
{
  "origin": {
    "kind": "testspec-native",
    "source_change": "<change-name>"
  },
  "trust": {
    "status": "provisional",
    "basis": "prd-first"
  }
}
```

`testcase-review` 通过后可在评审报告中记录验证结论，但不得静默修改原始用例来源。

## 历史用例

- 来源明确、已验证的历史用例：可参考命名、前置条件和回归范围。
- 来源不明或未经验证的历史用例：只能作为提示，不得成为需求事实、优先级或预期结果依据。
- `origin`、`trust` 缺失、为空或互相矛盾时，Review 必须标记 `provenance-unknown`。

## TestLib 复用

- TestLib 不得替代 PRD。
- 只读取与当前模块相关的少量用例作为表达和回归参考。
- 当前需求变化时，历史用例不能阻止生成新测试点或新用例。
- TestLib 不存在时直接继续当前四步流程。

## 安全边界

- 不在元数据中写入密码、Token、Cookie、私有仓库地址或绝对路径。
- 未经用户明确授权，不访问真实接口或生产系统来推导预期结果。
