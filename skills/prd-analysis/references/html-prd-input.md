# HTML 需求输入审查

HTML 可能包含可执行交互。需求分析前，在本地可执行副本中盘点页面、可达交互状态和按钮类控件，并逐项验证安全可执行的控件。页面行为是 **observed（观察到）** 的材料，不自动等于 **intended（需求意图）** 或验收 Oracle。

## 最小审查清单

1. **固定输入范围**：记录 HTML 入口文件、来源/版本（若有）、本地依赖资源及无法取得的资源；打开本地副本，不使用个人登录态。不能运行或关键资源缺失时，记录受影响页面和原因，不推断其内容。
2. **盘点页面和状态**：列出所有页面，以及从入口通过本地交互可到达的弹窗、展开区、标签页、表单反馈等状态。逐一检查当前可见控件；每次操作后发现的新页面、状态或控件继续纳入清单，直到没有新的可达项。以页面/路由和可观察状态描述状态，避免把同一控件在不同状态下的结果合并。
3. **为控件分配稳定 ID**：对按钮及等价点击控件按文档顺序分配唯一 `BTN-001`、`BTN-002`……。包括原生按钮、按钮型 input、`role=button`、自定义点击控件，以及作为界面操作入口的链接。记录可区分它的文案/可访问名称和 DOM/CSS 定位；重复文案需补充父区域或其他定位。下游引用沿用同一 BTN ID；来源版本变化时重新核对映射。
4. **逐项操作和记录**：在本地隔离浏览器中逐一点击可安全执行的控件，记录点击前状态、动作和点击后可观察结果，并保存截图、录屏或页面/控制台记录等可复核证据。新出现的状态继续盘点。不得仅凭文案或控件名称补写结果。
5. **控制副作用**：外链跳转、表单提交、发送消息、删除、支付及其他可能改变外部状态的动作，先使用无个人凭据的隔离环境和可控测试目标；必要时拦截/模拟外部请求。无法安全隔离或无法判断副作用时，不执行，状态记为 `not_executed` 并说明原因。
6. **核对需求映射**：每个 BTN ID 必须映射到 canonical 需求中的明确需求 ID，或映射到待澄清项。分别记录来源明确写出的 **intended** 和点击观察到的 **observed**；缺少意图、两者冲突或点击结果无法解释时，建立待澄清项。点击现象本身不能升级为需求事实或 Oracle。

## 控件记录结构

每个控件在每个相关页面/状态各有一条记录；同一控件跨状态沿用 BTN ID。

| 字段 | 填写内容 |
|---|---|
| `btn_id` | 稳定唯一 ID，如 `BTN-001` |
| `page_state` | 页面/路由与点击前可观察状态 |
| `control_locator` | 可区分控件的文案/可访问名称及 DOM/CSS 定位 |
| `status` | `clicked`（已点击）、`disabled`（禁用）、`unreachable`（不可达）、`not_executed`（未执行）之一 |
| `action` | 实际执行的点击动作；未点击时写明未执行/无法执行原因 |
| `observed` | 点击后的实际可观察变化；未点击时说明无法观察 |
| `intended` | 需求原文或需求 ID 的明确预期；没有明确依据写“未定义” |
| `evidence` | 文件/页面/状态、截图或其他证据位置；未覆盖项也须提供状态依据 |
| `requirement_or_question` | canonical 需求 ID，或对应待澄清项 ID；不得留空或根据观察结果臆造 |

`disabled` 需记录禁用状态的可见/语义证据；`unreachable` 需记录所在页面/状态及不可达原因；`not_executed` 需记录未执行原因和副作用风险。三者不表示已验证点击后的行为。

## 完成判定

- **审查记录完整**：入口及可达页面/状态均已盘点；每个控件在每个相关状态均有 BTN ID、定位、状态、证据及需求/澄清映射；禁用、不可达、未执行项均有原因。汇总各状态数量，并单列未覆盖项。
- **交互行为验证完整**：所有可达且可安全执行的启用控件均为 `clicked`，并有实际结果证据。存在 `not_executed`、未能打开的页面或未覆盖状态时，只能报告审查记录完整/部分完成，不能称全部交互已验证。
- 任何影响需求预期的缺失或冲突保留为待澄清；相关范围在获得明确意图前不得生成确定性 Oracle。下游使用 BTN ID 保持控件、需求/澄清项与测试覆盖之间的追溯。
