# 蓝湖 PRD 输入适配

当用户提供蓝湖邀请链接、PRD 链接或 Axure 文档时，先把蓝湖内容当作需求输入，再进入 `prd-analysis`。蓝湖阅读不是独立流程，不会改变四步链路：

`Lanhu PRD → prd-analysis → test-points → testcase-generate → testcase-review`

## 默认读取路径

优先使用本 Skill 自带的直连脚本，不要求本地 MCP 或桥接环境：

```bash
python3 "<prd-analysis-skill-dir>/scripts/direct_extract_axure.py" --url '<蓝湖链接>'
```

脚本默认处理全部页面，并在本地输出目录写入 `manifest.json`、每页 `page_record.json` 与页面资源；可用 `--output-dir '<本地目录>'` 指定保存位置。命令行只显示覆盖摘要和清单路径；先核对 `manifest.json` 的页面、文字和图片数量及失败项，再逐页读取 `page_record.json`，按清单逐张打开本地图片读取内容。`extraction_status=incomplete` 时命令返回码为 `2`，须逐项处理缺口；`reading_status=pending_visual_review` 表示图片尚未完成视觉阅读。资源下载完成只代表素材已取得，不能代替视觉阅读。

需要分享密码时：

```bash
python3 "<prd-analysis-skill-dir>/scripts/direct_extract_axure.py" --url '<蓝湖链接>' --password '<分享密码>'
```

需要登录态时，按 `lanhu-prd-reader` 的方式，在本机创建 `~/.codex/lanhu-mcp-bridge/lanhu-mcp-local.env`，只配置完整 Cookie：

```env
LANHU_COOKIE='从已登录蓝湖请求头复制的完整 Cookie'
```

保持 Cookie 为单行，文件权限设为 `600`，不要提交到仓库或发到聊天。脚本会自动读取该文件；`LANHU_COOKIE` 环境变量和 `--cookie` 可临时覆盖它。页面资源与清单仅保存在本机指定目录，不把 Cookie 写入需求产物。

## 全量页面与图片阅读

默认按文档版本枚举全部页面，逐页获取可用的页面数据、文字和图片资源；不能只看页面名称，也不能只读取某一个页面。用 `pages` 与 `sitemap` 交叉核对页面清单，记录每页处理状态。

对每页发现的图片，必须取得图片内容并逐张视觉阅读：记录图片中的文字、界面状态、控件、流程和功能规则；纯装饰图也要明确分类。图片路径、哈希、下载成功或 OCR 结果，都不能单独证明已读懂图片。页面文字与图片文字应合并核对，保留各自的页面和图片位置，避免同一页面的隐藏状态、弹窗或长图部分被漏掉。

交付前核对页面总数与已处理页数、每页发现图片数与已读取图片数，以及文字和图片来源是否可追溯。任何页面、文字资源或图片无法取得/辨认时，列出具体页面、资源和原因，标记阅读未完成；不得声称“已读完全部内容”，也不得把缺失内容推断成需求事实。涉及功能规则或预期结果的缺口进入阻塞澄清项，补齐后再把该范围交给 `test-points`。

静态 Axure 文件无法展示的交互状态，需要在可访问的原型中逐状态查看；若原型不可访问，同样记录为未覆盖，而不是默认不存在。

## 进入需求分析

1. 把蓝湖链接、页面名称、可见文案、交互规则和截图事实记录为 `requirements.md` 的需求来源。
2. 在 `requirements.md` 中注明来源链接或页面位置；保留原始事实，不把页面分组推断写成需求事实。
3. 蓝湖只提供需求材料，不能替代用户确认的业务规则；不清晰的页面行为进入阻塞澄清项。
4. 继续按 `prd-analysis` 的四类功能覆盖和上下文协议生成 `requirements-analysis.md`，并把 `source_revision` 原样传播给后续步骤。

## 信息不足时的降级

- 直连解析失败、链接需要登录或页面缺少文本：明确标记缺失事实，继续分析已确认内容；必要时请用户提供分享密码、页面名或截图。
- 只有在用户明确要求深度读取且本地已配置桥接时，才尝试 Lanhu MCP；MCP 不可用时回到直连/人工确认。是否能进入 `test-points` 由素材阅读完整性与功能规则缺口决定。
- 不访问生产系统，不根据当前接口响应反推业务预期；网络请求仅用于读取用户明确提供的蓝湖文档。

## 事实与推断

输出需求分析时分开记录：

- **已确认事实**：蓝湖页面或文档明确写出的文案、规则、状态和模块。
- **分析推断**：页面分组、可能的状态关系或测试风险，必须注明“推断”。
- **待确认事项**：影响测试设计或验收判断的缺失、歧义和冲突。
